# Languages

Rule: no user-facing string literals in components. Text goes through `t()`, numbers and dates through `format`, both from `useI18n()`.

## Setup

- Nine languages: `en` (source of truth), `nl`, `de`, `tr`, `es`, `fr`, `it`, `pt` (Brazilian wording), `ru`.
- No i18n library. `expo-localization` only reads the device locale (`useLocales`), and its config plugin in `app.json` lists the same languages for the system per-app language setting.
- `src/i18n/index.ts`:
  - `LANGUAGES`
  - `translate(language, key, params, tag)`
  - `resolveLanguage`: saved choice → first supported device language → English
  - `resolveTag`: the device tag when it is in the chosen language, so the region is kept; otherwise the language default
  - `pluralForm`: written out, no `Intl.PluralRules`
  - `tNow`: for code outside React

## Keys

- `src/i18n/locales/en.ts` is a flat `as const` map of dotted keys with `{name}` placeholders.
- Plural groups are `key_one` / `key_other` (Russian adds `_few` / `_many`) and are called by base name with a `count` param: `t('common.transactions', { count })`.
- Other locales are typed `Translations`, so `tsc` fails on a missing key.
- Add a key to `en.ts` and to all eight other files.
- `site.*` keys are used by the website build only ([website.md](website.md)).

## Provider

- `LanguageProvider` (`src/contexts/LanguageContext.tsx`) is the outermost provider inside `SQLiteProvider`.
- The saved choice is in `app_meta` (`language`, empty = follow the device) and is read synchronously on launch.
- `useI18n()` gives `t`, `format`, `categoryName`, `describe`, `language`, `storedLanguage`, `setLanguage`.
- Components take `t` from `useI18n()`, never `tNow`: React Compiler memoizes components and only the context value changing re-renders them.
- `tNow` is for `src/utils/notifications.ts` and similar. The provider keeps the module-level language in step and re-schedules reminders (`refreshImportReminderText`) when the language changes.

## Formatting

`format` (`src/i18n/format.ts`, `createFormatters(tag)`):

- `money(value, symbol, decimals | options)` (symbol in front)
- `number`, `date`
- `day('YYYY-MM-DD', withYear)`
- `range(from, to)`
- `monthYear('YYYY-MM', 'long' | 'short')`
- `shortMonth(index)`

No `toLocaleString('en-US')` and no hardcoded month / weekday names.

## Category names

- Built-in category names stay English in the database: the classifier, rules, budgets and backups depend on them.
- `categoryName(name)` translates them on display (`src/i18n/categories.ts`). Custom and renamed categories show as typed.
- Search and filters still compare the stored English name.

## Text built outside React

- It is returned as a `Message` (`{ key, params }`), not a string:
  - fixed / flexible reasons (`scoreFixed`, `getFixedResolver`; `FixedExplanation.reason` is a `Message[]`),
  - review suggestions (`CategorySuggestion.reason`),
  - Freedom field errors (`FreedomErrors`),
  - Budget Health (`biggestImprovement`, `health_alerts.message` stored as JSON).
- Render with `describe(messages)` (joins with commas, sentence-cases, translates a `category` param) or `t(message.key, message.params)`.
- Option lists (`DEBT_TYPE_OPTIONS`, `DEBT_TERM_UNITS`, Freedom field configs) hold a translation key in `label`.
- `SCENARIOS` keeps its English `label` for the tests; the UI uses `SCENARIO_LABELS`.
- `getYearCoverageStatus` returns status and dates only; Home and Trends build the coverage badge text.
- Unsupported-file messages in `src/utils/statementFormat.ts` stay English (the tests match on them); `UNSUPPORTED_MESSAGE_KEYS` maps each to its key for the alert.

## Left in English on purpose

- Theme names.
- Stored profile names (`Personal`, `Demo Workspace`).
- Demo seed data.
- Parser keywords.
- `console.*`.
- `BANK_LABELS` (bank names in the import summary).
- Package names and license texts on the Open-Source Licenses screen.
- The components that are not wired up (listed in `CLAUDE.md`).
